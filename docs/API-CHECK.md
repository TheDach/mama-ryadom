# Проверка API

Роль проверки: обычный пользователь. Административный доступ не требуется.

## Локальная проверка

```bash
npm run api:check -- --local
```

Команда поднимает временный сервер с базой в памяти, создаёт отдельные демопрофили и закрывает сервер после проверки. Рабочая база не меняется. Проверяются авторизация, семишаговая анкета, подбор, личные статусы, настройки, напоминания, изоляция сессий, конфликт версии и удаление.

Для уже запущенного локального демосервера:

```bash
npm run api:check -- http://localhost:3000 --demo
```

## Опубликованный API

Используйте отдельный пустой тестовый аккаунт MAX, которым ещё не проходили опрос. Проверка изменяет профиль и удаляет его в конце. Основной аккаунт для этой команды не подходит. Скрипт отклоняет профиль с уже сохранёнными ответами, напоминаниями или личными отметками.

1. Откройте мини-приложение из нужного бота в веб-версии MAX.
2. В инструментах разработчика получите значение `window.WebApp.initData` либо `WebAppData` из URL-фрагмента. Это подписанная строка целиком, без повторного URL-декодирования.
3. Передайте значение через переменную окружения MAX_INIT_DATA. Не записывайте его в исходники, DATA-API, отчёт или историю репозитория.
4. Запустите проверку, пока стартовые данные действительны:

```bash
npm run api:check -- https://mama-ryadom-production.up.railway.app
```

Скрипт получает Bearer-сессию самостоятельно. Значения сессии и initData в вывод не попадают. По окончании удалите MAX_INIT_DATA из окружения. В Linux/macOS: `unset MAX_INIT_DATA`; в PowerShell: `Remove-Item Env:MAX_INIT_DATA`.

## Переменные DATA-API

DATA-API.yaml содержит описания динамических параметров. Объект `value_from` означает подстановку целого значения с сохранением типа, а не передачу объекта буквально:

| Ссылка | Значение | Тип |
|---|---|---|
| env.MAX_INIT_DATA | Подписанные стартовые данные тестового аккаунта | string |
| auth.token | token из POST /api/auth | string |
| state.version | version последнего ответа состояния | integer |
| state.flow | flow текущей анкеты | string |
| future.dueAt | Текущее время + 1 час в ISO 8601 с часовым поясом | string |

Для заголовка Authorization к auth.token добавляется префикс `Bearer `. После каждого изменения берётся новая версия состояния. При повторном использовании прежней версии ожидается HTTP 409. Встроенная команда воспроизводит эти запросы автоматически; формальную схему подключения DATA-API к платформе оценки согласует организатор.

OpenAPI 3.1 находится в openapi.json. В локальном деморежиме вместо подписанных данных используется `{"demo":true}`; в опубликованной версии с DEMO_MODE=false такой вход запрещён.
