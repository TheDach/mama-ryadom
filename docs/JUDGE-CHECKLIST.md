# Проверка для жюри

## Локальная воспроизводимость

1. Распаковать архив. Убедиться, что `.env` и `.env.example` присутствуют, токен пуст.
2. Выполнить `docker compose up --build -d`; открыть http://localhost:3000.
3. Нажать «Попробовать демоверсию», открыть подбор, заполнить тестовый профиль из README.
4. Проверить №1 как потенциальную меру и №4 как уточнение. Источники, дата, маркировка тестовых данных присутствуют.
5. Открыть №1 → добавить в мои → «Готовлю документы». На главной меняется прогресс, в «Моих заявках» есть мера.
6. Сменить этап на 0–1,5 года и доход на «Не знаю». Подборка меняется; доходные меры требуют уточнения, нет категоричного отказа во всей поддержке.
7. Каталог: поиск, категория, канал, статус, этап. Сбросить фильтры. Выбрать 2–3 меры и сравнить. Четвёртая не выбирается.
8. Настройки: тёмная / системная тема, размер текста, режим для слабовидящих. Проверить клавиатуру и 320/390/768/1440 px.
9. Включить уведомления о незавершённых действиях, открыть карточку, задать будущее время. Напоминание сохраняется; локальное демо честно сообщает, что без диалога MAX доставка невозможна.
10. Остановить / запустить контейнер: профиль и статус в существующей вкладке сохраняются. Новый браузерный demo-вход создаёт отдельного пользователя.
11. Удалить профиль в настройках. Старый bearer перестаёт работать.
12. `npm test` и `npm run check` проходят.

## Обязательная проверка в MAX после подключения

1. Заполнить переменные, связать mini app с ботом и зарегистрировать webhook по README.
2. Открыть бот в мобильном клиенте MAX → `/start` → «Подобрать поддержку» → согласие → два ответа.
3. `/start` → «Продолжить опрос»: следующий вопрос, предыдущие ответы сохранены.
4. Завершить опрос, выбрать несколько оформленных мер и «Готово».
5. Получить summary и «Ближайший шаг» прямо в чате, проверить документы и организацию.
6. «Посмотреть подборку» открывает mini app внутри MAX. Профиль совпадает с ботом. Внешняя браузерная демосессия не подходит для этой проверки.
7. Изменить профиль в mini app → `/result` в боте показывает пересчитанный набор.
8. Сохранить меру и поменять статус → перезапустить mini app → статус сохраняется.
9. В mini app включить уведомления, запланировать через 1–2 минуты. Дождаться сообщения MAX. `/stop` отключает дальнейшую отправку.
10. `/life` → обновить профиль после рождения → набор меняется.
11. Открыть старую кнопку вопроса: анкета не повреждается.
12. Повторить пункты 2–10 в MAX Web. Проверить deep link конкретной карточки и обратно к каталогу.
13. Временно отключить сеть в клиенте → понятная ошибка / возможность повторить. Опрос в боте остаётся доступным, если недоступен лишь адрес mini app.
14. `/delete` → подтверждение → ответы, статусы, настройки и напоминания удалены.

## Материалы сдачи

Заполнить `docs/submission.json`; адрес API в `DATA-API.yaml` и `openapi.json`; служебный слайд презентации. Зафиксировать SHA-256 архива либо commit hash репозитория. Для публичных материалов использовать пустой BOT_TOKEN. Обеспечить доступность MAX и API на весь период проверки. Нельзя считать локальное демо заменой работающего решения в MAX.
