# Запуск и развёртывание

## Локальная проверка

Docker Engine и Compose v2:

```bash
docker compose up --build -d
```

http://localhost:3000 открывает демоверсию. Если в папке уже есть `.env`, Compose использует его значения. Для проверки без MAX в нём должны быть `DEMO_MODE=true` и пустой `BOT_TOKEN`.

Node.js 24:

```powershell
Copy-Item .env.example .env
npm ci
npm start
```

Копирование примера требуется только при отсутствии `.env`. В существующем проекте настройки сохраняются.

## Railway

Репозиторий содержит Dockerfile. Секреты задаются в переменных сервиса Railway.

| Переменная | Значение |
|---|---|
| `DEMO_MODE` | `false` |
| `BOT_TOKEN` | Токен бота |
| `BOT_USERNAME` | Ник без `@` |
| `PUBLIC_URL` | Постоянный HTTPS-адрес сервиса |
| `BOT_MODE` | `webhook` для сдачи |
| `WEBHOOK_SECRET` | Случайная строка от 32 символов |
| `DB_PATH` | `/app/var/mama.sqlite` |
| `NODE_EXTRA_CA_CERTS` | `/app/certs/russian_bundle.crt` |

Приложение читает `PORT`, который передаёт хостинг. Healthcheck использует тот же порт. `.env` не копируется в образ. Для SQLite нужен постоянный том с точкой монтирования `/app/var`. Количество экземпляров: один.

После развёртывания проверяется `/api/health`. Ответ должен содержать `status: ok` и `version: 1.1.0`. Затем в окружении запущенного сервиса выполняется `node scripts/max-setup.js`. Скрипт регистрирует webhook и команды бота.

В исходной конфигурации PUBLIC_URL был ссылкой перенаправления vk.ru/away.php. Для приложения нужен прямой адрес: `https://mama-ryadom-production.up.railway.app`. Значение без пути, query и фрагмента проверяется при старте.

Связь мини-приложения с ботом на стороне MAX сохраняется, если `PUBLIC_URL` не менялся. Кнопка открытия доступна в меню бота независимо от завершения анкеты. Постоянная кнопка платформы настраивается отдельно от кода проекта.

## Docker на собственном сервере

HTTPS завершается на обратном прокси. Пример конфигурации Caddy: `docs/Caddyfile.example`. Публичный домен направляется на сервер. Прокси передаёт запросы в `127.0.0.1:3000`.

Окружение можно хранить вне папки репозитория:

```bash
docker compose --env-file /secure/mama.env up --build -d
docker compose --env-file /secure/mama.env exec app node scripts/max-setup.js
```

Файл окружения передаёт настройки контейнеру при запуске. Публичный HTTPS-адрес принадлежит прокси или хостингу. Внутри контейнера приложение слушает обычный HTTP.

## Ошибки

| Симптом | Проверка |
|---|---|
| Конфигурация требует BOT_TOKEN и HTTPS | Значения окружения запущенного сервиса, `DEMO_MODE`, `PUBLIC_URL` |
| TLS `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` | Доступность `NODE_EXTRA_CA_CERTS`, содержимое доверенного bundle |
| Ошибка 502 | Логи приложения, совпадение порта сервиса и `PORT`, состояние `/api/health` |
| Бот не получает события | Режим polling/webhook, зарегистрированная подписка и секрет |
| Подпись MAX не совпадает | Мини-приложение открыто из нужного бота и использует его токен |
| HTTP 409 при сохранении | Профиль изменился в другом окне или боте. Обновить данные и повторить действие |

Проверка TLS не отключается. Токен, заголовок Authorization и стартовые данные MAX в журналы не записываются.
