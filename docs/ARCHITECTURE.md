# Архитектура и развитие

## Границы продукта

Приоритетный сценарий: беременная или родитель маленького ребёнка в Томской области хочет понять, какие меры проверить и куда обращаться. После опроса сервис показывает объяснение подбора, документы и следующий шаг.

Сейчас человек сопоставляет сведения из разных источников и отдельно хранит заметки о документах и сроках. Проект объединяет этот участок пути в MAX. Подача заявления и решение о назначении остаются у ведомства. Польза конкретного сценария пока является гипотезой, пилот не проводился.

## Компоненты

Один процесс Node.js обслуживает HTTP, Bot API и очередь напоминаний. Встроенный `node:sqlite` хранит профиль, черновик, личные статусы, настройки и сессии. Внешних npm-зависимостей нет.

`src/domain/questionnaire.js` содержит 15 вариантов вопросов и выбирает путь из 6-7 шагов. Этот модуль используют сервер и браузер. `src/services/questionnaire.js` выполняет переходы и меняет идентификатор `flow` после каждого действия. Бот и HTTP API используют одну функцию перехода.

`src/domain/questions.js` проверяет входные профили и настройки. Старые завершённые профили остаются совместимыми. Незавершённый опрос прежней версии начинается с первого шага с сохранёнными ответами.

`src/domain/eligibility.js` сопоставляет ответы с правилами. Источники и суммы находятся в `data/benefits.json`, условия в `data/rules.json`. Неизвестные значения дают уточнение, а не подтверждённое право. Новые возрастные категории уточняют объяснение результата.

`src/services/profile.js` предоставляет одинаковое состояние обоим интерфейсам. Версия записи защищает от перезаписи изменений из другой вкладки или бота. Незавершённый черновик не заменяет основной профиль.

## MAX и данные

Подпись `initData` проверяется на сервере по официальному алгоритму HMAC-SHA256. Проверяются возраст запуска и повторяющиеся параметры. Клиент получает непрозрачную сессию. В SQLite хранится её хеш.

Кнопки опроса используют `callback` с идентификатором текущего шага. Старый callback не меняет ответы после возврата назад или перехода из приложения. Callback содержит исходное сообщение бота, поэтому его sender.is_bot не используется для отбрасывания нажатия. Повторные события дедуплицируются. В webhook-режиме подписка на события кнопок обновляется при запуске. Бот читает актуальный профиль при каждом запросе результата.

Webhook проверяет отдельный секрет. Запросы ограничены по размеру и частоте. Проверяется Origin. При размещении за общим прокси лимит запросов действует на адрес прокси. Для большого пилота потребуется лимитирование на входном прокси с корректной обработкой доверенных адресов.

Напоминания хранятся в SQLite. Перед отправкой проверяется выбранный тип уведомлений. После временного сбоя действует повтор с задержкой. При сбое между отправкой и фиксацией результата возможна повторная доставка. Автоматического расчёта государственных сроков нет.

## Масштабирование

Следующий предполагаемый регион: Новосибирская область, затем Кемеровская. Это план, региональные наборы пока не реализованы.

Без изменений переносятся опрос, личный список, карточки и адаптер MAX. Для каждого региона нужны собственные меры, правила, источники, документы, организации и контрольные профили. Потребуются редактор данных, экспертная проверка и журнал обновлений. Выбор региона и загрузка нескольких наборов пока не реализованы.

Последовательность развития: проверка томского каталога, пилот, исправление ошибок по наблюдениям, второй регион. Реальные интеграции требуют согласованного доступа к информационным системам. Для нескольких экземпляров приложения SQLite заменяется серверной БД, отправка напоминаний выносится в очередь с блокировкой заданий.

## Пилот

План: 50-100 добровольцев в Томской области. Возможные каналы привлечения: МФЦ и ЦСПН после согласования. Договорённостей пока нет. Первые исследовательские сессии используют вымышленные профили.

Сравниваются самостоятельный поиск и сценарий в MAX. Измеряются время до результата, завершение опроса, понимание следующего шага и число тупиков.

Целевые значения для проверки гипотезы: завершение не ниже 80%, результат за 3 минуты, верное понимание следующего шага не ниже 80%, тупики менее 5%. Это плановые показатели. Приложение хранит обезличенные события начала и завершения анкеты, а также изменения личного списка. Опросы удовлетворённости и полноценная исследовательская аналитика потребуют отдельной организации.

Удаление профиля очищает его кэш ответов MAX; для повторного подтверждения удаления остаётся только обезличенный идентификатор события. Отложенная обработка напоминания не восстанавливает удалённый профиль.
