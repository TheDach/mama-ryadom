# Архитектура и развитие

## Проблема и граница решения

Беременная или родитель маленького ребёнка в Томской области знает свою ситуацию, но должен сопоставить условия нескольких мер и каналов обращения. Кейс описывает разрыв между цифровыми сервисами и полным жизненным процессом. Навигатор сокращает именно ручное сопоставление: не заменяет оформление пособия.

Текущий путь: поиск → разные сайты → сопоставление условий → выяснение документов → повторный поиск. Предлагаемый: MAX → восемь ответов → объяснимый результат → следующий шаг → личный трекер.

## Компоненты

MAX Bot API ↔ адаптер бота → сервис профиля → правила + каталог → SQLite.
Mini app → REST API с проверенной сессией MAX → тот же сервис профиля → та же SQLite.
Worker → сохранённые напоминания → MaxClient → MAX.

Предметный слой не зависит от MAX или HTTP. Каталог хранит контент, `rules.json` — условия, региональный файл — параметры территории. Правила возвращают совпадения, несовпадения и неопределённость отдельно. Next action выбирается по приоритету среди актуальных потенциальных мер и уточнений.

Бот сохраняет черновик, индекс вопроса и nonce опроса. После финального ответа профиль заменяется целиком. Старые кнопки не могут применяться к новой анкете. Мини-приложение меняет профиль атомарно, передавая версию. Отправка ботом нового результата всегда читает текущее состояние.

## Безопасность и эксплуатация

Неподписанный MAX ID не используется для входа. Проверяются HMAC, возраст запуска, уникальность параметров. Сервер выдаёт непрозрачную сессию, в SQLite хранится только SHA-256 токена. Запросы к пользовательским данным привязаны к сессии, не к переданному клиентом ID. HTTP ввод ограничен 32 КБ. В API есть лимит запросов на IP и проверка Origin. Прокси не должен подменять/добавлять доверенный пользовательский ID. При работе за одним прокси лимит общий для его адреса: для большого пилота перенесите rate limiting на ingress с проверенными IP.

Вебхук защищён отдельным секретом. Ответ и изменение состояния фиксируются транзакционно; повторное событие не повторяет изменение. Доставка может повториться после сетевой неоднозначности. SQLite предназначена для одного процесса; для нескольких инстансов потребуется PostgreSQL и очередь задач с блокировкой обработки.

## Масштабирование

Первый следующий регион — Новосибирская область: близкая аудитория, тот же федеральный слой и отдельный региональный набор. Второй — Кемеровская область. Это план, не реализованные наборы.

Переиспользуются: опрос, движок правил, карточки, личный трекер, подпись MAX, уведомления. Меняются: источники, критерии, документы, организации, ПМ, коэффициенты, версии данных. Перед расширением нужен редактор региональных сведений, экспертная проверка, контрольная выборка профилей и новая версия набора. Для выбора нескольких регионов потребуется добавить поле region в профиль и загрузчик соответствующего пакета; сейчас выбран один регион.

Порядок: проверить томский сценарий → уточнить правила и возрастные интервалы → поддержать 0–7 лет → новый регион → согласованные интеграции. Подключение государственных данных зависит от законных оснований, договорённостей и технического доступа.

## Пилот и метрики

Гипотеза: короткий подбор помогает понять следующий шаг быстрее, чем самостоятельный поиск. План пилота — 50–100 добровольцев целевого сегмента Томской области с привлечением через согласованные каналы МФЦ / ЦСПН. Договорённостей с этими организациями пока нет.

До пилота: проверить каталог специалистом, определить оператора данных, подготовить политику, выполнить MAX mobile/web checklist. В первой исследовательской сессии использовать вымышленные профили. Сравнить время и точность следующего шага до/после, провести CSAT/SUS; наблюдать возвраты, ошибки и причины уточнения.

Цели-гипотезы: ≥80% завершения, ≤3 минуты до результата, ≥80% правильно называют следующий шаг и организацию, <5% тупиков. Эти показатели не измерены и не заявлены как результат продукта. SQLite хранит анонимные события начала/завершения анкеты и обновления трекера; полноценная аналитическая воронка карточек и CSAT требует исследовательского инструмента. После пилота сначала исправляются ошибки и непонятные переходы, затем расширяется аудитория.
