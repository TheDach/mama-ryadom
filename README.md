# МАМА рядом

<img src="public/logo.png" width="96" height="96" alt="Логотип МАМА рядом">

Подбор мер поддержки для беременных и семей с маленькими детьми в Томской области. Бот MAX задаёт вопросы, показывает подходящие записи каталога и следующий шаг. В мини-приложении доступны условия, документы, источники, личные отметки и напоминания.

Версия 1.1.0. Приоритетная аудитория: беременные и родители детей до 3 лет. Для детей от 3 до 7 лет в каталоге есть ограниченный набор мер.

Каталог демонстрационный. Суммы и условия требуют проверки в официальных источниках. Приложение не отправляет заявления и не получает решения ведомств.

## Запуск

Все локальные компоненты запускаются одной командой. Нужны Docker Engine и Docker Compose v2.

```bash
docker compose up --build -d
```

Адрес: http://localhost:3000. Без `.env` Compose запускает браузерную демоверсию с отдельным тестовым профилем. Она не требует токена MAX. При наличии `.env` Compose использует его значения.

Для запуска без Docker нужен Node.js 24.x. Проверено на 24.19.0. Внешних npm-зависимостей у приложения нет.

```bash
cp .env.example .env
npm ci
npm start
```

В Windows PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`. Существующий рабочий `.env` заменять не нужно.

```bash
npm test
npm run check
npm run api:check -- --local
```

`npm run dev` запускает сервер с перезапуском при изменениях. Сервер, API и интерфейс используют один порт.

## Пользовательский сценарий

1. `/start` в боте MAX или открытие связанного мини-приложения.
2. Согласие на сохранение вымышленных ответов для демонстрации.
3. Опрос из 6 или 7 шагов. Срок беременности и возраст младенца уточняются только в соответствующих ветках. Состав семьи и занятость влияют на следующие вопросы.
4. Подборка с причинами совпадения и перечнем сведений, которые нужно уточнить.
5. Карточка выплаты: документы, срок, организация, официальный сайт и следующий шаг.
6. Сохранение выплаты в личный список, изменение отметки и напоминание в MAX.

В банке 15 вариантов вопросов. Два шага объединяют связанные сведения: состав семьи с очередностью ребёнка, гражданство с регистрацией. Каждый подтверждённый шаг сохраняется на сервере. Опрос можно начать в боте и продолжить в приложении. При смене этапа срок беременности или возраст ребёнка из прежней ветки удаляется. Уже оформленные выплаты сохраняются.

Профиль обновляется после завершения опроса. До этого подборка использует последние сохранённые ответы. Кнопка «Назад» возвращает предыдущий шаг, `/edit` начинает редактирование.

Настройки оформления и уведомлений находятся в одной форме. «Подтвердить» сохраняет их вместе. Тема и размер текста доступны для предпросмотра. «Отменить» возвращает сохранённые значения. Планирование напоминаний находится в карточках и разделе «Мои выплаты».

## Подключение MAX

Необходимы выданный организаторами токен, username бота, публичный HTTPS-адрес и исходящий доступ сервера к MAX API. Приложение подключается к существующему боту. Адрес подключения на платформе должен совпадать с `PUBLIC_URL`.

Для опубликованной версии:

```dotenv
DEMO_MODE=false
PUBLIC_URL=https://your-domain.example
BOT_USERNAME=your_bot
BOT_MODE=webhook
```

`BOT_TOKEN` и `WEBHOOK_SECRET` передаются через окружение сервера. Локальный `.env` исключён из Git и Docker-образа. Пример файла не содержит секретов.

Генерация секрета webhook:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

После настройки окружения:

```bash
docker compose up --build -d
docker compose exec app node scripts/max-setup.js
```

Скрипт проверяет доступ к боту, задаёт команды и регистрирует webhook. В режиме webhook приложение также обновляет подписку при запуске: в ней обязательно включён `message_callback`. При временной ошибке настройка повторяется через 30 секунд. Без Docker используется `npm run max:setup`. Режим polling предусмотрен для разработки. Его нельзя запускать одновременно с действующей webhook-подпиской.

MAX API: `https://platform-api2.max.ru`. Сертификаты из `certs/russian_bundle.crt` подключаются через `NODE_EXTRA_CA_CERTS`. Проверка TLS включена. Публичные сертификаты доверия не являются приватными ключами.

Порядок развёртывания на Railway и обычном Docker-сервере: [docs/QUICKSTART.md](docs/QUICKSTART.md).

## Окружение

| Переменная | Пример или значение по умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | пусто | Токен выданного бота |
| `BOT_USERNAME` | пусто | Ник без `@`, для открытия мини-приложения |
| `PUBLIC_URL` | `http://localhost:3000` | Внешний адрес, HTTPS для MAX |
| `DEMO_MODE` | `true` в Compose и примере | Браузерный вход с вымышленным профилем |
| `BOT_MODE` | `polling` | `webhook` для опубликованной версии |
| `WEBHOOK_SECRET` | пусто | 32-256 символов: латиница, цифры, `_`, `-` |
| `PORT` | `3000` | Порт Node.js, Compose фиксирует 3000 |
| `HOST` | `0.0.0.0` | Адрес прослушивания |
| `DB_PATH` | `./var/mama.sqlite` | База, в контейнере `/app/var/mama.sqlite` |
| `MAX_API_URL` | `https://platform-api2.max.ru` | Адрес API MAX |
| `NODE_EXTRA_CA_CERTS` | `./certs/russian_bundle.crt` | Дополнительные сертификаты доверия |
| `INIT_DATA_TTL_SECONDS` | `3600` | Допустимый возраст подписанного запуска |
| `SESSION_TTL_SECONDS` | `86400` | Срок сессии приложения |

При прямом запуске Node без `.env` режим демонстрации не включается автоматически. Настройки платформы хостинга имеют приоритет над значениями `.env` при запуске через Node.

## Состав проекта

| Каталог | Содержимое |
|---|---|
| `src/domain/` | Вопросы, ветвление, валидация и подбор |
| `src/services/` | Профиль, переходы опроса и каталог |
| `src/max/` | Bot API, подпись запуска, доставка сообщений |
| `src/http/` | HTTP API и файлы интерфейса |
| `src/storage/` | SQLite, сессии и версии состояния |
| `public/` | Мини-приложение на HTML, CSS и JavaScript |
| `data/` | 18 записей каталога, правила, тестовые профили |
| `tests/` | Правила, опрос, бот, API, хранение и напоминания |
| `docs/` | Проверка, архитектура, ограничения и презентация |

Один процесс Node.js обслуживает бот, интерфейс и API. SQLite хранит общий профиль. MAX Bridge предоставляет подписанные данные запуска. Фреймворки интерфейса не используются. React и MAX UI не являются обязательными условиями кейса.

## Данные и ограничения

Каталог перенесён из предыдущей версии проекта без актуализации сумм. Каждая запись содержит источник, дату исходного материала и `testData=true`. Дата источника не означает дату юридической проверки.

- Правила объясняют совпадения, несовпадения и недостающие сведения. Результат не подтверждает право на выплату.
- №10 требует дополнительных сведений об аренде и возрасте родителей. №11-14 относятся к будущему расширению. Эти записи доступны в каталоге, но не входят в автоподбор.
- №17 и №18 дублируют каналы оформления №1 и №3. Личные отметки привязаны к основной записи.
- Суммы разных периодов не складываются. Категория дохода выше 1,5 ПМ не доказывает превышение 2 ПМ.
- Нет связи с СФР, ЕГИССО, Госуслугами, работодателями и региональными системами. Их статусы и ответы не имитируются.

Подробности: [docs/ELIGIBILITY.md](docs/ELIGIBILITY.md), [docs/SOURCES.md](docs/SOURCES.md).

Хранятся категориальные ответы и технический ID MAX. ФИО, паспорт, СНИЛС, точный адрес, доход и документы не запрашиваются. `/delete` и кнопка в настройках удаляют профиль и отзывают сессии. Связанный кэш ответов MAX удаляется вместе с профилем. Остальные события, включая недоставленные, очищаются по сроку хранения до 7 дней, обезличенные счётчики действий до 90 дней. Резервные копии контролирует владелец сервера. Для пилота с реальными сведениями нужны правовое основание обработки и политика оператора.

## API и проверка

Контракт: [openapi.json](openapi.json). Проверки для кейса: [DATA-API.yaml](DATA-API.yaml). Основные методы:

- `GET /api/health`, `GET /api/config`.
- `POST /api/auth`: подписанный вход MAX или отдельный demo-профиль при `DEMO_MODE=true`.
- `GET /api/state`, `PUT /api/questionnaire`, `PUT /api/profile`.
- `PUT /api/tracking/{benefitId}`, `POST /api/reminders`, `DELETE /api/state`.

Для изменений нужны сессия Bearer и текущая `version`. Для шагов анкеты дополнительно передаются `flow` и `questionId`. Конфликт возвращает HTTP 409. Секреты MAX не передаются в клиент. Общего тестового пароля или административного входа нет.

Контрольный профиль: беременность, 30 недель и больше, один первый родной ребёнок, трудовой договор, гражданство РФ и постоянная регистрация, доход ниже ПМ, выплат нет. Ожидается №1 с результатом «Потенциально подходит», №4 с уточнениями. Профиль с ранним сроком беременности требует уточнить время оформления отпуска.

Проверка по шагам: [docs/JUDGE-CHECKLIST.md](docs/JUDGE-CHECKLIST.md). Фактически выполненные проверки: [docs/TEST-REPORT.md](docs/TEST-REPORT.md).

## Остановка и данные контейнера

```bash
docker compose stop
docker compose start
docker compose logs --tail=100 app
docker compose down
```

`down` сохраняет volume. Команда `docker compose down -v` удаляет базу. Обновление: `docker compose up --build -d`.

Для резервной копии приложение останавливается. Каталог `/app/var` копируется целиком, включая WAL/SHM при их наличии. После копирования контейнер запускается снова. При восстановлении нужен владелец UID 1000. База рассчитана на один экземпляр приложения.

## Материалы сдачи

В `docs/submission.json` хранятся реквизиты проверки. По ним скрипт `scripts/build-presentation.py` формирует `docs/presentation.pdf`. Для генератора нужны Python 3, зависимости из `docs/requirements.txt` и Unicode-шрифт. Приложение и Docker не требуют Python.

```bash
python -m pip install -r docs/requirements.txt
python scripts/build-presentation.py
npm run release:check
```

В Windows путь к шрифту задаётся через `PRESENTATION_FONT`, например `C:\Windows\Fonts\arial.ttf`. Перед сдачей заполняются служебный слайд, адреса OpenAPI и DATA-API. Секреты для технической проверки передаются жюри приватно в порядке, установленном организаторами. В репозиторий они не входят.

Сдаваемая версия фиксируется commit hash либо архивом с SHA-256. Доступность MAX, проверка в двух клиентах, сборка Docker до 5 минут и заполненные реквизиты проверяются перед отправкой. [docs/CASE-COMPLIANCE.md](docs/CASE-COMPLIANCE.md) содержит соответствие требованиям и оставшиеся внешние проверки.

Перенос изменений в отдельную ветку: [docs/GIT-BRANCH.md](docs/GIT-BRANCH.md).

## Исправления от 30.09.2026

Обработчик кнопок использует пользователя из `callback.user`. Исходное сообщение в callback принадлежит боту и больше не отбрасывается проверкой `sender.is_bot`. Собственные сообщения бота по-прежнему игнорируются. При отклонении callback-ответа MAX показывает результат новым сообщением.

Превышение лимита напоминаний возвращает сообщение пользователю. Проверка статусов и настроек допускает только собственные ключи справочников. Удаление профиля очищает связанный кэш, отменяет напоминания и отзывает сессии. Существующая база SQLite обновляется при открытии.

Проверка файлов без рабочего окружения MAX и без оценки презентации:

```bash
node scripts/release-check.js --source-only --without-presentation
```

В `docs/submission.json` используется название проекта «МАМА рядом». Если официальное название команды отличается, замените поле `team`. Поле `deploymentVerified` устанавливается в `true` только после реальной проверки опубликованной версии. Контрольная сумма исходников не включает этот файл и MANIFEST.sha256, чтобы реквизиты можно было заполнить без циклического вычисления хеша.

Готовый сценарий API описан в `docs/API-CHECK.md`. Проверка Docker и повторного запуска подготовлена в workflow Verify; факт её выполнения в этом архиве не заявляется.
