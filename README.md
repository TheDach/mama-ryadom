# МАМА рядом

Персональный навигатор по мерам поддержки для беременных и родителей детей до 3 лет в Томской области. Бот MAX проводит опрос и показывает следующий шаг. Связанное мини-приложение раскрывает условия, документы, источники и личный прогресс. Категория 3–7 лет предусмотрена для просмотра ограниченного демонстрационного набора.

**Весь каталог — тестовые данные из приложенного Khakaton (2)(2).docx.** Результат не подтверждает право на выплату. Приложение не подаёт заявления и не получает статусы ведомств. Нельзя использовать его для юридически значимых решений.

## Быстрый запуск

Требуются Docker Engine и Docker Compose v2. Из корня проекта выполните:

```bash
docker compose up --build -d
```

Откройте http://localhost:3000 и нажмите «Попробовать демоверсию». В архиве уже есть `.env` с пустым `BOT_TOKEN`. Браузерное демо работает без токена и не отправляет сообщения. После заполнения токена в режиме polling бот также начинает работать; для полноценного мини-приложения нужен публичный HTTPS-адрес и привязка к боту.

Локальный запуск без Docker: **Node.js 24.x** (проверено на 24.19.0). Внешних npm-зависимостей нет: HTTP, SQLite, тесты и загрузка `.env` используют Node.js.

```bash
npm ci
npm start
```

`npm run dev` — перезапуск при изменениях. `npm test` — автоматические тесты. `npm run check` — проверка синтаксиса и файлов поставки. Сервер и мини-приложение используют один порт 3000.

## Основной сценарий

1. Пользователь открывает бота MAX и отправляет `/start`.
2. Видит назначение, маркировку тестовых данных и согласие на сохранение категорий ответов.
3. Отвечает на 8 вопросов: этап, первый ребёнок, число детей, занятость, доход относительно ПМ, гражданство, регистрация, оформленные меры.
4. Получает число потенциальных мер, уточнений и оформленных выплат. «Ближайший шаг» показывает документы, организацию и срок прямо в чате.
5. Кнопка «Посмотреть подборку» открывает связанное мини-приложение с тем же профилем.
6. В карточке пользователь проверяет объяснение, сохраняет меру, меняет личный статус и при желании планирует напоминание.
7. Изменённый профиль влияет на следующий ответ бота `/result` или `/next`.

Если мини-приложение недоступно, опрос и короткий результат остаются в боте. Незаконченный опрос бота сохраняется в SQLite. Черновик формы мини-приложения сохраняется в текущей вкладке браузера; окончательное сохранение синхронизирует оба интерфейса.

## Подключение к MAX

Для реального запуска нужны токен созданного бота MAX, его username, сервер с HTTPS на 443 и доступ сервера к MAX API. В архиве этих реквизитов нет: их предоставляет владелец бота.

1. Создайте или используйте выданного бота на платформе MAX. В `.env` заполните `BOT_TOKEN` и `BOT_USERNAME` (без `@`, только ник).
2. Разместите приложение на сервере. Проксируйте HTTPS-запросы на `127.0.0.1:3000`. Пример конфигурации — `docs/Caddyfile.example`; TLS-прокси и домен являются инфраструктурой развёртывания, приложение локально работает одной Docker-командой.
3. Укажите `PUBLIC_URL=https://ваш-домен`, `DEMO_MODE=false`, `BOT_MODE=webhook`. Сгенерируйте секрет командой ниже и вставьте в `WEBHOOK_SECRET`.
4. Укажите `PUBLIC_URL` как адрес мини-приложения, связанного с этим ботом, в настройках платформы MAX. Это отдельное действие владельца аккаунта.
5. Пересоздайте контейнер и зарегистрируйте команды и webhook:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
docker compose up --build -d
docker compose exec app node scripts/max-setup.js
```

При запуске без Docker: `npm run max:setup`. Скрипт проверяет бота через `/me`, задаёт меню команд и регистрирует webhook с секретом. Токен в журнал не выводится. Проверка подписи mini app использует HMAC-SHA256 по официальному алгоритму MAX, проверяет дубликаты полей и возраст `auth_date`. Идентификатор из неподписанного запроса клиента не принимается.

Для разработки можно оставить `BOT_MODE=polling`, `DEMO_MODE=true` и запустить `npm start`. Polling не работает одновременно с webhook-подпиской. Скрипт настройки предупреждает о существующих подписках, но не удаляет их автоматически. Для публикации нужен webhook.

API MAX использует `https://platform-api2.max.ru` и заголовок `Authorization`. При ошибке доверия к сертификату установите доверенный сертификат в окружение Node через `NODE_EXTRA_CA_CERTS` и смонтируйте файл в контейнер. Не выключайте проверку TLS. Требования платформы описаны в `docs/SOURCES.md`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | пусто | Токен MAX; без него работает только локальное демо |
| `BOT_USERNAME` | пусто | Ник бота для кнопок открытия mini app |
| `PUBLIC_URL` | `http://localhost:3000` | Внешний адрес; для MAX и webhook нужен HTTPS |
| `BOT_MODE` | `polling` | `polling` для разработки, `webhook` для публикации |
| `WEBHOOK_SECRET` | пусто | Случайные 32–256 символов A–Z, a–z, 0–9, `_`, `-` |
| `DEMO_MODE` | `true` | Разрешает отдельные синтетические браузерные профили; при публикации `false` |
| `PORT` | `3000` | Порт Node.js; внутри Compose фиксирован 3000 |
| `HOST` | `0.0.0.0` | Адрес прослушивания; Compose публикует только 127.0.0.1 |
| `DB_PATH` | `./var/mama.sqlite` | SQLite; в Compose `/app/var/mama.sqlite` |
| `MAX_API_URL` | `https://platform-api2.max.ru` | MAX Bot API |
| `INIT_DATA_TTL_SECONDS` | `3600` | Максимальный возраст подписанного запуска |
| `SESSION_TTL_SECONDS` | `86400` | Время действия сессии приложения |

`.env` **намеренно отсутствует в `.gitignore` по вашему требованию**. В поставке токен пустой. Кейс запрещает рабочие секреты в репозитории: после заполнения не добавляйте рабочий `.env` в коммит или публичный архив. Публикуйте копию с пустыми значениями, либо передавайте секреты через окружение сервера. `.dockerignore` исключает `.env` из образа; Compose передаёт значения во время запуска. `.env.example` не содержит рабочих секретов.

## Структура

| Каталог / файл | Ответственность |
|---|---|
| `src/domain/` | Вопросы, валидация, независимый движок правил |
| `src/services/` | Каталог, профиль, трекер, напоминания |
| `src/storage/` | SQLite, транзакции, версии, сессии, журнал событий |
| `src/max/` | Клиент MAX, опрос, подпись, polling и доставка напоминаний |
| `src/http/` | REST API, webhook и выдача интерфейса |
| `public/` | Адаптивное mini app без сборщика и внешних UI-зависимостей |
| `data/benefits.json` | Все 18 исходных записей, суммы, документы, даты и источники |
| `data/rules.json` | Условия и причины уточнения отдельно от контента |
| `data/regions/` | Региональная конфигурация |
| `data/demo-profiles.json` | Воспроизводимые синтетические профили |
| `tests/` | Правила, подпись MAX, бот, API, SQLite, напоминания |
| `docs/` | Проверка для жюри, архитектура, ограничения, PDF-презентация |
| `scripts/` | Проверка кода, настройка MAX, проверка готовности и сборка PDF |
| `openapi.json` | Контракт API OpenAPI 3.1 |
| `DATA-API.yaml` | Описание проверок собственного API для кейса |
| `var/` | Рабочая база, не входит в архив результатов |

Один Node.js-процесс обслуживает API, статику, бот и напоминания. Оба интерфейса обращаются к одной SQLite-базе. ESM-модули разделяют платформенный адаптер и предметную логику. JavaScript выбран по требованию пользователя; React в кейсе рекомендован, но не обязателен. Фронтенд использует стандартные DOM API.

## Данные и правила

Все 18 записей перенесены из дополнительного DOCX и маркированы `testData=true`. Дата `updatedAt` — дата в исходном материале, **не дата юридической проверки**. Некоторые источники — сторонние сайты, что отдельно отмечено в интерфейсе. Официальный портал предоставляется отдельной ссылкой, когда он определён; это не глубокая ссылка на подачу заявления.

Модель сознательно не делает юридически точных расчётов. Противоречия исходника обработаны консервативно: «выше 1,5 ПМ» не означает «выше 2 ПМ»; широкая возрастная группа не подтверждает шестимесячный срок. Для таких случаев возвращается «Требует уточнения». Полная матрица — `docs/ELIGIBILITY.md`.

- №11–14 остаются в каталоге, но исключены из автоподбора MVP. Флаг многодетности сохраняется/вычисляется по профилю.
- №10 требует сведений об аренде и возрасте родителей, поэтому также вне автоподбора.
- №17 и №18 — каналы тех же пособий №1 и №3. Они не увеличивают количество мер в подборке.
- «Первый родной ребёнок» и «трое детей в семье» допустимы одновременно: учитываются дети супруга, подопечные и приёмные.
- Неизвестный доход и временная регистрация приводят к уточнению, отсутствие регистрации — к несовпадению регионального критерия.
- В интерфейсе раздельны результат rules engine и ручной статус пользователя. Даже «Подано» / «Получено» — личные отметки.
- Суммы хранятся как текст исходника. Районный коэффициент повторно не умножается. Нет общего «итого»: суммы разных периодов и дубли не складываются.

Для обновления региона измените данные, правила и версию набора, внесите тестовый профиль и ожидаемый результат в тесты, проверьте источники профильным специалистом. Не выдавайте непроверенные записи за действующие нормы.

## API и тестовые учётные записи

Полный контракт — `openapi.json`. Для демонстрации администратор не нужен. В MAX пользователь авторизуется подписью платформы. Общих тестовых логинов, паролей или универсальных токенов нет. В локальном режиме `POST /api/auth` с `{"demo":true}` выдаёт изолированную сессию. Повторный вход создаёт новый профиль. Вкладка хранит bearer-токен в `sessionStorage`.

Основные методы: `GET /api/state`, `PUT /api/profile`, `PUT /api/tracking/{benefitId}`, `POST /api/reminders`, `DELETE /api/state`. Изменения требуют `version` из последнего состояния; при конфликте — HTTP 409. Это защищает от незаметного перетирания изменений между ботом и mini app.

`DATA-API.yaml` содержит проверки, параметры, роль и ожидаемые ответы. После публикации замените адрес и подставьте подписанную сессию MAX. Символические значения `CURRENT_VERSION_FROM_STATE` и `FUTURE_ISO_DATETIME_WITH_TIMEZONE` обозначают значения, которые проверяющий берёт из предыдущего ответа / задаёт на момент проверки. Машинная схема файла организаторами в PDF не задана; перед сдачей согласуйте этот формат.

## Надёжность и данные пользователя

SQLite использует WAL и транзакции. Ответы бота сохраняются до доставки; повтор callback не применяет ответ анкеты повторно. Устаревшая кнопка не изменяет текущий вопрос. Ошибки MAX повторяются с задержкой. Напоминания сохраняются, отправляются при включённом соответствующем типе уведомлений и повторяются после временного сбоя. Время вводится пользователем и хранится в UTC, отображается в часовом поясе устройства. Бот предлагает напоминание через 24 часа; календарь государственных сроков автоматически не рассчитывается.

В редком случае сбоя между отправкой в MAX и фиксацией результата напоминание может повториться: API не предоставляет приложению сквозной ключ идемпотентности. Получение статуса доставки не имитируется.

Храним технический ID MAX и категориальные ответы. Не запрашиваем имя, паспорт, СНИЛС, адрес, точный доход или медицинские документы. `/delete` и удаление из настроек очищают профиль и отзывают его сессии. Технический журнал дедупликации хранится до 7 дней, агрегируемые события воронки без ID — до 90 дней. Резервные копии удаляются владельцем развёртывания по установленному сроку хранения. Для реального пилота понадобятся правовое основание обработки и политика оператора.

## Проверка и ожидаемое поведение

Подробный сценарий — `docs/JUDGE-CHECKLIST.md`. Основной тестовый профиль: беременность → первый ребёнок → 1 ребёнок → работает → ниже ПМ → гражданство РФ → постоянная регистрация → ничего не оформлено. Ожидается №1 «Потенциально подходит», №4 «Требует уточнения», следующий шаг — №1. После смены этапа на 0–1,5 года набор пересчитывается. Неизвестный доход не блокирует сценарий.

Фактически выполненные проверки и ограничения среды перечислены в `docs/TEST-REPORT.md`. Интеграционные тесты MAX используют подставной транспорт и подписанные тестовые данные; они не заменяют проверку вашего бота в мобильном и веб-клиенте MAX.

## Остановка, перезапуск и резервное копирование

```bash
docker compose stop
docker compose start
docker compose logs --tail=100 app
docker compose down
```

`down` сохраняет named volume. `down -v` удаляет базу — используйте только для намеренного сброса. При обновлении: `docker compose up --build -d`. Один экземпляр приложения на одну SQLite-базу; горизонтальное масштабирование не поддерживается.

Для согласованной резервной копии остановите приложение, затем скопируйте `/app/var` из остановленного контейнера через `docker cp` (ID получите командой `docker compose ps -aq app`), после чего запустите его. Копируйте весь каталог, включая WAL/SHM, если они есть. Для восстановления остановите контейнер, верните каталог в volume и восстановите владельца UID 1000. Не публикуйте базу с реальными профилями.

## Перед сдачей кейса

В комплекте есть `docs/presentation.pdf` и исходник генератора. Служебный слайд честно отмечает отсутствие реквизитов развёртывания. Заполните `docs/submission.json`, перегенерируйте презентацию (инструкция ниже) и внесите HTTPS-адрес в OpenAPI / DATA-API. Выполните `npm run release:check`, пройдите сценарий в обеих версиях MAX и обеспечьте доступность сервера на весь период проверки. Токены передавайте проверяющим только по разрешённому приватному каналу; не добавляйте их в публичные исходники или публичную презентацию.

Перегенерация PDF — необязательная операция документации: Python 3 и `reportlab==4.4.9`, `pip install -r docs/requirements.txt`, затем `python scripts/build-presentation.py`. Приложение и Docker не требуют Python.

Архив исходников и его SHA-256 заменяют Git-репозиторий с commit hash согласно кейсу. Если создаёте репозиторий, укажите настоящий hash. Не придумывайте ссылку на бота или результаты пилота.

## Известные ограничения

Нет реальной интеграции с СФР, ЕГИССО, Госуслугами, работодателями или региональными системами. Нет подачи заявлений и загрузки документов. Нет индивидуальных профилей каждого ребёнка и юридически точного расчёта права. Суммы не актуализируются автоматически. Не реализованы функции из списка Could: экспорт чек-листа и административная панель. Публичное развёртывание, создание бота и проверка с реальным токеном выполняются владельцем инфраструктуры.

Архитектура, план масштабирования и пилота — `docs/ARCHITECTURE.md`. Связь поставки с требованиями PDF — `docs/CASE-COMPLIANCE.md`.
